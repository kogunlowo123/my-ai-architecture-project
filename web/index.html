Two regulated domains, one hard problem

A probabilistic model, handed deterministic capabilities

Both industries fail agents the same way: not on accuracy, but in security review. So both get the same primitives — and only the domain agents differ.

Healthcare payer operations

Enterprise payer · HIPAA · PHI behind a FHIR gateway

  • T2Prior-auth triage — evidence + recommendation; a licensed reviewer decides. Denials never auto-execute.
  • T3Claims navigator — status enrichment and plain-language EOB explanations, reversible and rate-capped.
  • T1Member-services copilot — agent-assist for CSRs; the human owns the conversation.

Transaction tax compliance

Tax platform · sales & communications tax · audit defense

  • T3Determination assist — mapping, situs, rate lookup from versioned content. Every input vector stored, replayable.
  • T2Exemption certificates — extract, validate, stage behind human approval.
  • T2Filing readiness — reconciliation and anomaly flags; a human signs every filing, always.

The shared control plane

orchestrator enforces tiers · workload identity issues 15-minute audience-bound tokens per agent (OAuth 2.1 exchange — no confused deputies) · audit chain hash-links every action · MCP servers are the only path to systems of record, with signed, pinned tool schemas · eval gates decide promotion.

Governance

Autonomy is earned, like a probation period

The question isn't "autonomous agents: yes or no?" It's "what has this agent proven, and what blast radius are we prepared to accept?" Demotion is automatic; promotion never is.

Compliance by construction

Controls that survive a security review

Every control maps to a named requirement, so the review moves in days, not quarters.

Hash-chained audit

Every capability invocation links to the previous event's hash; heads are KMS-signed and checkpointed to Object-Locked storage.

HIPAA §164.312(b) · SOC 2 CC7.2 · ISO 27001 A.8.15 · ISO 42001 8.4

Per-agent identity

No shared service accounts. Each agent exchanges its own identity for a 15-minute, audience-bound, scope-bound token.

HIPAA §164.312(a) · SOC 2 CC6.1 · ISO 27001 A.5.16

Signed tool schemas

MCP schemas are pinned in lock files and verified at session start — a schema swap becomes a reviewed diff, not an attack.

Tool-poisoning defense · SOC 2 CC8.1

Human approval gates

T2 actions execute only with a verified approval token from a separate human principal — never the agent's credential.

HIPAA §164.308(a)(3) · SOC 2 CC5.1

Eval promotion gates

Tier changes require committed eval reports against golden sets; regressions on any version change trigger automatic demotion.

ISO 42001 8.3/9.1 · SOC 2 CC7.1

Kill switch + hard limits

T3 boundaries are machine-enforced; one trip halts the agent platform-wide and pages the owner. Silence in the audit stream is itself an alarm.

Runaway-autonomy defense · ISO 27001 A.8.16
